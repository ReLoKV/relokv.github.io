Introduction

This page documents the experimental workloads, configurations, comparisons, and measurements for ReLoKV. The evaluation studies whether task-return prediction, cross-LoRA KV representations, dependency-aware cache management, and background execution can reduce repeated prefill and memory pressure on resource-constrained devices.

The experiments are designed to distinguish an adapter prediction from a reusable session, a legal exact-prefix match, a prepared KV state, and a state actually consumed by a request. These are separate events and are reported separately. This site contains experimental materials only; it does not host the manuscript or describe the full system design.

Workloads and Data Preparation

We study two complementary workload patterns:

1) Sequential conversations: a session grows over multiple turns, is interrupted by other tasks, and may later be revisited. Requests preserve the chronological conversation history.

2) Parallel document tasks: different compatible LoRA adapters process tasks derived from a shared source document, with non-consecutive returns to earlier tasks.

Behavior traces and text content are constructed separately. Mobile application traces provide temporal order; dialogue or document datasets provide request text. App-to-task, task-to-adapter, and session mappings are experimental annotations, not native labels supplied by those datasets. The selected dataset versions, filtering rules, mapping procedure, and licenses will be recorded with each release.

Train, validation, and test partitions follow user and time boundaries. Text is deduplicated by source conversation or document before partitioning. The test period is not used to construct transition statistics, choose anchors, tune thresholds, or select model checkpoints. Workloads include negative cases such as new sessions, incompatible adapters, changed prefixes, low-reuse periods, and long return intervals.

Workload Statistics

Each workload release will report the number of users, sessions, requests, tasks, and adapters; input and output token distributions; session-return intervals; adapter-switch rates; exact-prefix opportunities; and the fraction of requests with a known prior session. These statistics are reported separately for natural traces and controlled sensitivity workloads.

Experimental Setup

The initial target is an NVIDIA Jetson AGX platform running llama.cpp. Exact board model, memory capacity, power mode, clocks, cooling conditions, and software revisions will be reported for each measured configuration. The initial model is Qwen2.5-1.5B-Instruct; Llama-3.2-1B-Instruct is planned as a cross-family evaluation. Adapter compatibility is checked against the exact base model and recorded per run.

Comparisons use the same request inputs and order, model precision, tokenizer, prompt template, generation settings, physical-memory budget, and maximum background-work budget. JetPack, CUDA, driver, operating system, llama.cpp revision, compiler flags, model versions, adapter versions, and decoding parameters are pinned in the environment manifest. Planned configurations are not treated as verified platform support until the corresponding runs complete.

We compare against no reuse, exact same-LoRA prefix reuse, demand-only preparation, adapter-only preload, and relevant KV compression or cache policies. Reimplementations of related mechanisms are identified as such. Baselines that do not support a feature are not given an artificial advantage through a different request sequence or resource budget.

Prediction and Preparation

Prediction is evaluated using only history visible at the decision time. Methods include stay, LRU, popularity/LFU, Markov, context-aware, short-history GRU, and relation-fusion predictors. Training seeds, history windows, and candidate counts are selected using validation data and then fixed for the test period. Time-order and user-boundary checks guard against future leakage.

We report Top-k accuracy and mean reciprocal rank alongside the service-relevant preparation funnel: predicted adapter, known-session match, legal exact-prefix match, valid recovery dependencies, readiness before arrival, and actual consumption by the matching request. We also measure predictor latency and memory, unused or expired preparation, cancellation, and interference with foreground requests.

Comparisons include demand-only preparation, adapter-only preload, and adapter preload with legal historical-KV preparation. Candidate count, preparation window, return interval, and prediction errors are varied under a fixed background-work budget. A predicted adapter is not counted as a KV hit; new request text that has not yet arrived is not treated as known input.

Cross-LoRA KV Representation

For the same model and exact prefix, a target adapter's KV state may be represented relative to an anchor adapter. We compare complete KV storage, direct KV quantization, and anchor-delta representations. Grouping strategies and anchor selection are evaluated using training or calibration data only; test data is not used to create groups or choose anchors.

Measurements include separate key and value reconstruction errors, bytes for the complete family including metadata, first-construction time, restoration time, temporary peak memory, recovery failures, and downstream output quality. First construction is charged for the target KV and any extra prefill required. Comparisons use compatible adapters and identical prefix tokens. Similarity metrics alone are not treated as evidence of equivalent task quality.

Grouping and anchor ablations vary the grouping method, anchor choice, adapter-pair sampling, and delta precision while holding the request workload and memory budget fixed. Both storage savings and the end-to-end cost of recovering a usable target KV are reported.

KV Management Policies

We compare complete-KV retention, block-level eviction, leaf eviction, session-path management, anchor-family dependency management, and joint policies where applicable. The comparison holds total physical memory and request order constant. Shared parent data is counted once; metadata, conversion buffers, and restoration peaks are included.

Measurements include usable continuous-prefix coverage, bytes actually released, number of recoverable sessions, dependency violations, restoration latency, temporary memory peak, and request-level TTFT. Ablations remove or vary prediction, frequency, dependency impact, prefix depth, and preparation-cost signals. Dependency and version checks remain enabled for all valid policies.

We include cases where a relatively cold anchor supports several frequently used descendants, as well as cases where retaining a whole family costs more than recomputation. This exposes whether a policy's apparent hit rate translates into usable state under a fixed physical-memory budget.

Background Execution

Background work includes delta construction, KV restoration, and layer-wise prefetch. We first isolate kernel fusion, multi-layer task organization, and transfer behavior in local microbenchmarks. Integrated tests compare serial execution, stream-based execution, layer-wise recovery, load-aware deferral, and adapter-aware batching.

Experiments cover idle, prefill-heavy, decode-heavy, and bursty foreground load. CUDA-event timelines are paired with host wall-clock measurements to account for synchronization, waiting, memory-bandwidth contention, and foreground slowdown. We report background backlog, cancellation, memory peaks, and energy as well as the fraction of work that overlaps in time. Stream priority alone is not assumed to guarantee preemption or interference-free execution.

End-to-End Evaluation and Ablations

End-to-end replay evaluates sequential conversations and parallel document tasks under representative physical-memory budgets. Main outcomes are request-level TTFT and ITL distributions, throughput, usable KV reuse, peak physical memory, energy, failures, and service-level objective outcomes. Results are paired by workload and run wherever the comparison permits.

System ablations remove prediction, cross-LoRA KV compression, dependency-aware eviction, and asynchronous execution separately, then examine interactions among them. Stress tests vary adapter count, context length, return distance, switch probability, arrival rate, prediction quality, and preparation budget. Low-reuse and incorrect-prediction cases are included to measure when preparation should be skipped or cancelled.

Independent process replays and predictor training seeds are recorded separately. Representative configurations use at least three replays and three predictor seeds initially; repetition may be increased based on measured variability. Uncertainty is assessed at the user, trace, or independent-run level, rather than treating correlated requests as independent users.

Quality, Energy, and Correctness

Restored or compressed KV states are compared with the same target adapter's original full-KV execution. We report logit-level differences where available, task-quality measures, and output checks with tolerances defined before evaluation. Non-significance alone is not treated as evidence of equivalence.

Energy experiments specify whether foreground work, background preparation, idle periods, and waiting are included. Sustained runs record power, temperature, backlog, leaks, errors, and completion outcomes. Directed correctness tests cover adapter or model version changes, anchor eviction, cancellation, prefix mismatch, bursty requests, and buffer synchronization.

Experimental Artifacts

Materials are released only after their inputs, versions, permissions, and outputs have been checked. At present, the repository provides experiment documentation, a request-field schema, an environment metadata template, and detailed reproduction requirements. The schema is a field dictionary, not a request trace; the JSON file is a metadata template, not a runnable configuration.

Request traces, executable implementation, checkpoints, measured result files, and plotting scripts are not included in this initial version. No end-to-end performance gain or successful reproduction is claimed here. Each artifact will be linked only when the corresponding release is available.
